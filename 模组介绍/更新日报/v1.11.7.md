# v1.11.7 更新日报

**日期**：2026-10-08
**类型**：修复（战利品修改器写错 id → 核心永远开不出来）
**jar**：`mcmcp_warehouse-1.11.7.jar`

## 问题（很严重）

自动化核心改成"只能在遗迹宝箱里找到"后，用的是全局战利品修改器。
里面有一个条件我写成了 **`minecraft:alternative`** —— 这在 **1.21.1 里不存在**。

去游戏里查了编译后的 MC 类：

```
net/minecraft/world/level/storage/loot/predicates/
    AllOfCondition.class
    AnyOfCondition.class          ← 1.21 里改名成这个了
    （没有 AlternativeLootItemCondition）
LootItemConditions 里注册的 id：all_of / any_of / entity_properties / inverted / random_chance
```

所以正确 id 是 **`minecraft:any_of`**（字段名还是 `terms`）。

**如果没查出来**：这个战利品修改器会解析失败 → 核心**永远不会出现在任何宝箱里**，
玩家会以为"遗迹里根本没有"，而日志里可能只有一行不起眼的报错。

## 修复

```json
{
  "condition": "minecraft:any_of",     // 原来是 minecraft:alternative（1.21.1 已不存在）
  "terms": [ { "condition": "neoforge:loot_table_id", "loot_table_id": "minecraft:chests/..." }, ... ]
}
```

## 这次把整条链路都逐个核对了一遍

| 环节 | 核对结果 |
|---|---|
| 战利品目录名 | `data/<ns>/loot_table/`（1.21 是单数）✅ |
| 物品条目字段 | `{"type":"minecraft:item","name":"...","weight":N}` ✅ 和原版箱子表一致 |
| 空条目 | `minecraft:empty` ✅（EmptyLootItem 存在） |
| 修改器类型 | `neoforge:add_table` ✅（NeoForge 源码注释里就是这么写的） |
| 修改器字段 | `conditions` + `table` ✅ |
| 条件 id | `neoforge:loot_table_id` ✅（NeoForgeMod.java:680 注册） |
| 清单文件 | `data/neoforge/loot_modifiers/global_loot_modifiers.json` ✅ |
| 旧合成配方 | 已从 jar 里彻底清除 ✅ |
| 复刻配方 | 1 核心 + 1 下界合金锭 + 7 钻石 → **2 个** ✅ |

> 结论：除了 `alternative` → `any_of` 这一处，其它格式都是对的。
