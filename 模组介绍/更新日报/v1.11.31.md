## 1. 修：开了 `/commhub selftrade true`，界面还是只有「取消悬赏」
> 「我打开了那个权限，但是为什么还是没有出现交易，只有取消悬赏」

原因：那个开关**只在服务端**，界面不知道 ✗
`TradeScreen` 判断"这是自己的悬赏" → 只给「取消悬赏」，永远不会给「接受」。

**改法**：把开关状态一起同步给客户端
- `SyncTrades` 数据包多带一个 `selfTrade` 布尔
- `ClientHubState.selfTrade` 保存
- 界面逻辑：

| 情况 | 按钮 |
|---|---|
| 别人的悬赏 | 接受 |
| 自己的悬赏（正常） | 取消悬赏 |
| 自己的悬赏 + 调试开关开着 | **取消悬赏 + 接受(调试)** ✅ |

## 2. 新增测试指令：召唤假人来交换（OP）
```
/commhub faketrade
```
流程：
1. 找你**最新发布**的那条悬赏（没有就提示先去发一条）
2. 召唤一个假人「**测试假人**」
3. 假人**凭空备齐**它要付的东西（测试专用；真玩家还是得背包/仓库里够）
4. 走**同一套交换逻辑** → 正常扣物、给物、发成交动画
5. 你会看到完整的「空间裂缝 + 铁链 + 箱子」动画

顺手把交换逻辑抽成了 `performTrade(accepter, owner, trade, data)` ——
以后玩家接受和假人接受走的是**同一段代码**，不会再出现"两套逻辑不一致"。

权限：`/commhub faketrade` 和 `/commhub selftrade` 都**只有 OP（等级 2）**能用 ✓
