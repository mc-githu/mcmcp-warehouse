# v1.11.29 更新日报

## 现象（用户报告）
> 「它显示数量不够，但是已经消耗的物品，这会吞物品。并且明明数量是够的，东西都扣除了。」

## 根因：`removeAvailable()` 里背包部分**扣了物品却忘记计数**

```java
// 背包部分
if (slot.getItem() == stack.getItem()) {
    int take = Math.min(slot.getCount(), remaining.getCount());
    slot.shrink(take);          // ← 物品从这里扣掉
    remaining.shrink(take);
    // ❌ 少了 removed += take;
}
// 仓库部分
    removed += take;            // ← 这里记得加
```

后果链条：
1. 背包里的物品**被扣掉**，但函数返回的 `removed` 是 **0**
2. 于是判定 `got < 要的数量` → 报「**数量不够**」
3. 回滚时只按 `got`（=0）归还 → **背包里扣掉的物品再也没还回来** → **吞物品** ✗✗

这也解释了你说的「明明数量是够的，东西都扣除了」——
其实物品确实够了，是**计数漏了**导致误判为不足，然后回滚又还了 0 个。

## 修复
```java
    slot.shrink(take);
    remaining.shrink(take);
    removed += take;            // ← 补上
```
另外把取消时的提示写清楚（说明已把扣掉的物品还回去）。
