# v1.11.26 更新日报

**日期**：2026-10-08
**类型**：以物换物一批修复 + 取用记录结构对齐
**jar**：`mcmcp_warehouse-1.11.26.jar`

## 1. 取用记录界面的结构改成和容器界面完全一致
用户指出「这就是你写的代码有问题」—— 对。
对比发现我的 `render()` 结构是自创的：

| | 正常的界面 | 我写的取用记录（糊） |
|---|---|---|
| 背景 | 走原版 `renderBackground` | 自己画一堆 fill |
| 顺序 | 背景 → 面板 → **控件** → 文字 | 面板 → 文字 → **控件（最后）** |

现在改成标准的五步：**背景 → 面板/框 → 列表内容 → 控件 → 文字**，和 `AbstractContainerScreen` 一模一样。

## 2. 以物换物：两个「发布悬赏」
左边栏那个其实是**切换模式**的，却和真正发布的按钮同名 ✗
→ 改成：**「悬赏模式」/「换物模式」** + 执行按钮 **「确认发布」**。

## 3. 显示的是物品内部 id（`create:cogwheel`）
悬赏里写的是 `3×create:cogwheel` 这种 ✗ 应该是**游戏里的名字**（齿轮）✓
- 内部逻辑仍然用 id（服务端要靠它认物品），**只在显示时翻译**成 `getHoverName()`
- 大数字也做了压缩显示：`12000 → 1.2万`、`100000000 → 1亿`

## 4. 幽灵格一格只能放 1 个
`setGhost` 里写死了 `copyWithCount(1)` ✗ 而且**原来有的「滚轮调数量」在我 1.11.20 重写时丢了** ✗
→ 现在：放物品时**保留手持数量**；**滚轮 ±1，按住 Shift ±64**；上限 = 无限堆叠。

## 5. 我给 / 我要 各 10 格
`TRADE_SLOTS` 5 → **10**（绘制、点击判定、JEI 拖拽都读同一个常量，自动跟着变）。
布局核对：10 格 = 110~288，框 106~294，面板 300，放得下 ✓

## 6. 以物换物支持无限堆叠（含存档）
- 幽灵格上限 = 1 亿（和仓库/邮箱一致）
- **存档修好了**：`ItemStack` 的存档 codec 上限是 **99**，超过会被截断 ✗
  → 改成「item 存压到 99 + 单独存 `Count`」，读档时 `setCount` 还原（与仓库同一套做法）
  - 兼容旧存档（旧格式直接就是 ItemStack 的 NBT）✓
- 溢出的物品本来就由 `giveToPlayer` 转进**邮箱**（邮箱无限）✓ 不会丢
