# v1.9.11 更新日报

**日期**：2026-10-07
**类型**：优化（仓库存储改为分页）
**jar**：`mcmcp_warehouse-1.9.11.jar`

## 改动：仓库存储改成「分页数组」

以前：仓库在内存里**一次性开一大块固定数组**（按配置的格数），容量是死的，空仓库也占着那块空间。

现在：仓库内部是**「每页 54 格」的数组列表**（`PagedItemHandler`）：

| 行为 | 说明 |
|---|---|
| **溢出自建新页** | 所有页都塞满时，插入会自动新建一页继续装 → **容量真正无限** |
| **空页不留** | 末尾整页空的会在存档时丢掉，**空仓库只占 1 页**，存档很小 |
| **按页导航** | 点「▶」翻到还没建立的页时，服务端自动补页 |
| **旧存档兼容** | 旧的扁平格式（`{Size, Items}`）会自动迁移到分页格式，**物品不丢** |

### 单格上限：99

顺带把「无限堆叠」的单格上限统一成了 **99**，原因（已在 MC 字节码里确认）：

```
ItemStack 的存档编码：
  20: iconst_1      ← 1
  21: bipush 99     ← 99
  23: invokestatic  ExtraCodecs.intRange(II)
```

即 **`count ∈ [1, 99]`**，超过 99 的堆叠**根本存不进存档**（`ItemStack.save()` 直接抛异常崩服）。
所以「单格真无限」在 MC 里无法持久化；以前那套「内存无限 + 存档前按 64 拆」会把玩家叠好的大堆**打散**，仓库满时还会**丢物品**。
现在统一成 99/格：**叠多少存多少，永不打散、永不丢弃**，配合分页 = 总量无限。

## 涉及文件

- 新增 `PagedItemHandler.java`（分页存储 + 存档 + 旧格式迁移）
- `HubSavedData`：共享仓库 / 私人仓库改用分页存储
- `HubMenu`：客户端镜像按页数建，`getMaxPages()` 按实际页数
- `ModNetworking`：翻页时按需扩页
- `WarehouseBlockEntity`：输入方块插入时自动扩页
