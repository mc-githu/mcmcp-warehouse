## 真正的原理

原版 `Screen.renderBackground()` 在 1.21 是这么干的：

```
renderBackground()
 ├─ renderBlurredBackground()   ← 先把世界渲到「另一张低分辨率缓冲」做模糊（另一个图层）
 └─ renderMenuBackground()      ← 再画背景
然后才画 GUI（renderBg / 按钮 / 文字）
```

也就是说**背景和按钮本来就不在同一个图层**。在部分 Android GL 翻译层
（这台机器是 MobileGlues）上，那个低分辨率缓冲的状态没被还原，
于是后面画的 **GUI 也被一起糊掉** —— 这就解释了「连原版按钮都是糊的」。

## 修法（同一图层）

我们自己的界面**不让背景走那条模糊后处理路径**，直接在**同一次 GUI 绘制**里画背景：

```java
@Override
public void renderBackground(GuiGraphics g, int mouseX, int mouseY, float partialTick) {
    this.renderTransparentBackground(g);   // 原版那层半透明深色渐变，纯 GUI 绘制
}
```

- 用的还是**原版的视觉效果**（半透明深色底，世界透出来但变暗），不是纯黑
- 但**不触发** `renderBlurredBackground()`，所以背景和按钮在同一个图层里
- 应用到 **6 个界面**：仓库主界面、取用记录、交易、好友列表、方块选目标、两张卡片配置

（v1.11.15 那版先改纯黑是错的 —— 背景会变成一整片黑；这一版用的是半透明渐变，正常。）
